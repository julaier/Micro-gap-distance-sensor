# LDC1614 V5：现有 C0 板 / 内部参考时钟对照

V4 实板结果：睡眠 `3601` 的立即回读、保持 1 秒均通过；唤醒 `1601` 的
最后低字节 `01` 收到 NACK，之后通信正常但多项配置回到复位默认值。
V5 不换板、不改变供电或接线，仅清除 CONFIG bit9，改用 LDC 内部参考：
睡眠 `3401`、唤醒 `1401`。这是单变量对照，不是已确认的修复。
具体 Keil 操作见 [DEBUG_KEIL.md](DEBUG_KEIL.md)。

独立工程，目录 `STM32C011F6U6TR/wake_test`。不修改正式固件或原 `test`。
保留原 `test/Driver/test_board.c`、`test_i2c.c` 原文件并直接编译复用，
不使用正式 `App/app.c`、`Device/ldc1614.c`、`Driver/hard_i2c.c`。
此目录依赖父工程的启动、CMSIS、LL 头文件和 `test`，不能单独移走。

## 下载哪个工程

打开 **`MDK-ARM/LDC1614_Wake_Test.uvprojx`**，目标 `LDC1614_Wake_Test`。
Keil 5 / ARM Compiler 6：F7 编译，确认零错误后手动 F8 下载，再复位。
下载会替换 MCU 当前运行程序；本工程没有修改 MCU 选项字节的代码。
若新工程未选择下载器，在 Options for Target → Debug / Utilities 中确认 ST-Link、
SWD，以及 `STM32C0x_32.FLM`。不要因此修改原正式工程的设置。

串口保持 **115200，8N1**，PA2 TX、PA3 RX；PB7 SCL、PB6 SDA；PA4 仅输入。
ADDR=GND，固定地址 `0x2A`；现有外部 40 MHz CLKIN 接法不变，但本版不选择它作为参考。
这不是关闭外部时钟模块，也不能排除仍连接的模块产生电气影响。
HSE 8 MHz 直接运行，HSE 失败时明确打印 HSI 回退，不使用 PLL。
I2C 是原 test 半拍至少 5 µs 的实现，加软件开销，不能声称实测 100 kHz。

程序版本标记必须是：

命令行仅编译，不下载：

输出 `MDK-ARM/Objects/LDC1614_Wake_Test.hex`。请保留从版本标记开始的完整日志，
直到 `$B,RESULT` 即可，无需反复发送相同的 MONITOR。

## V5 的一次性对照流程

通道参数与写入顺序仍取自 `new/Device/ldc1614.c`；保留 V4 手动固定驱动。
与 V4 相比，仅清除 CONFIG bit9；I2C 原语、MCU 时钟、接线、电流和其他寄存器参数不变。
内部参考频率不当作精确 40 MHz，本工程不运行测量换算或校准算法。
原来的唤醒事务后 5 ms 静默保留，不改从机 NACK 的判定。
全局 `g_wake_quiet=0` 仍可取消这 5 ms，但第一次测试请保留默认值，避免同时改变两个变量。

1. `1C=8000` 软复位一次，等待 5 ms，读取并验证 ID `5449/3055`。
2. 顺序写 `14/15=1001`、`10/11=0180`、`08/09=FFFF`、`1E/1F=9000`、`1B=820C`。
3. 读 `1A`，应为复位值 `2801`；不符则停止，不继续改写 CONFIG 或唤醒。
4. 写 `1A=3401`：内部参考、手动驱动、全电流传感器启动，**仍保持睡眠**。
5. 回读并校验全部稳定配置，记录为 `SLEEP_NOW`；不向串口打印。
6. 等待 1000 ms，其间不复位、不重初始化、不读写寄存器；再回读记录为 `SLEEP_1S`。
7. 只有睡眠写入收到 ACK，且两组快照的通信 / 配置校验均通过，才写 `1A=1401` 唤醒。
   这次相对于 `3401` **仅清除 bit13 睡眠位**；之前任一项失败就跳过唤醒。
8. 唤醒事务结束后，默认静默等待 5 ms：不读写 I2C、不打印、不复位、不切时钟。
   然后回读 CONFIG；即使写入 NACK 也读，但保留原写入失败，不把回读当成 ACK。
   这 5 ms 是诊断设置，不是手册要求必须等待 5 ms，也不能倒过来修复先前的 NACK。
9. 连续采集 `FIRST_READS`，等待 20 ms 后采集 `PLUS20MS`，之后才打印缓存的记录。
   若根本未执行唤醒，则只打印当前 `FINAL` 快照与 `WAKE,SKIPPED,-4`。
10. 此后每秒只读 ID、配置、状态和原始数据。无自动重试、软复位或内部参考回退。

CONFIG 位定义依据 TI SNOSCY9A 的 CONFIG 寄存器表（Table 27）：

- bit12 `RP_OVERRIDE_EN=1`：禁用初始自动传感器校准，采用 `IDRIVE` 字段。
- bit10 `AUTO_AMP_DIS=1`：禁用自动幅度校正。
- bit11 `SENSOR_ACTIVATE_SEL=0`：保留 V4 的全电流传感器启动。
- bit9 `REF_CLK_SRC=0`：内部参考；bit13：睡眠。

因此 V4 的 `1601/3601` 各清除 `0x0200` 后，本版为 `1401/3401`。
通道 `IDRIVE=9000` 不变；没有开启另一个 bit6 `HIGH_CURRENT_DRV` 功能。
这是诊断对照，不是已经确认“无传感器触发自动校准导致器件复位”。
不写 `19=0001`，不发送 V1 的 `0A01` 或旧正式固件的 `2A01`。
启动诊断只在整段采集完成后打印记录；并非宣称执行时间与旧 F103 硬件 I2C 相同。

不启动 SysTick、EXTI/NVIC、ADC、OLED、按键、看门狗、Flash 参数或测量算法。
TIM14 查询计时；不依赖 INTB。原有开关 / OLED 代码未删除，本工程不编译它们。
`main` 额外读取一次 STM32 的 `RCC->CSR2`，保存并打印原始十六进制值，再清除复位标志。
这只是 MCU 复位证据，不是 LDC 复位原因；没有修改选项字节或开启看门狗。

## 日志解释

```text
$W,<reg>,<写入值>,<写rc>,<阶段>,<payload下标>,<最后tx>,<ACK电平>,<STOP rc>,<时钟数>,<估算Hz>
$B,MCU_RESET_CSR2,<STM32原始复位标志，十六进制>
$B,ACTIVATE,FULL_CURRENT,SLEEP,3401,WAKE,1401
$B,WAKE_QUIET_MS,<本次选择的额外静默时间，默认5>
$B,CONFIG_BEFORE,<读rc>,<唤醒前CONFIG>
$S,1A,3401,<睡眠写rc>,<首次睡眠CONFIG读rc>,<首次睡眠CONFIG值>
$C,1A,<目标CONFIG>,<唤醒写rc>,<静默后读rc>,<静默后回读CONFIG>
$Q,<SLEEP_NOW/SLEEP_1S/FIRST_READS/PLUS20MS/FINAL/MONITOR>,<reg>,<实际读rc>,<值>
$K,<同上>,COMM,<本组寄存器读取的首个错误码或0>
$K,<同上>,HOLD,<保留校验rc>
$K,WAKE,SKIPPED,-4
$B,RESULT,<阶段或CONFIG_PASS_NOT_MEASUREMENT>,<rc>
```

寄存器、值、最后 tx 是十六进制；其余数字是十进制。
`$W` 的 payload 下标：0=寄存器，1=高字节，2=低字节，255=尚未发送 payload。
`REG` 表示写 payload 阶段，需结合下标；不是说每次都在写寄存器地址。
ACK 电平 0=应答、1=不应答；`rc=-2` 为 NACK、`-1` 为总线异常。
`-4` 是未尝试 / 尚未完成配置，不是读取出来的器件错误码。

`FIRST_READS` 是 CONFIG 静默后回读之后的第一组顺序读取；不是同时采样。
`PLUS20MS` 表示第一组读取结束后等待 20 ms 再读取，不是唤醒后恰好 20 ms。
`SLEEP_1S` 同样表示前一组读取结束后等待 1000 ms 再采集，不是精确的写入后 1 秒。
所有启动快照均在打印 `$W/$S/$C/$Q` 之前采集，不在采集之间插入串口打印。

HOLD 比较 `1A/1B/08/09/10/11/19/14/15/1E/1F`；`19` 预期为原版复位值 `0000`。
睡眠时 CONFIG 预期 `3401`；只有开始尝试唤醒后才改为预期 `1401`。
`0`=配置保持，`-18`=成功读取但不符，其余负值可能为实际总线错误。
本版关闭自动校正，`1E/1F` 仅比较可编程 `IDRIVE[15:11]`，预期均为 `9000 & F800`；
不比较只读 `INIT_IDRIVE` 字段，避免把只读字段变化误判成固定驱动电流丢失。
STATUS 和四个 DATA 寄存器也只观察，读取 DATA 可能消耗 unread 标志。
COMM 独立记录本组所有 `$Q` 读取的首个通信失败，不包含单独 `$D` 的两次 ID 读取。
即使 HOLD 先遇到配置不符而保持 `-18`，后续读取 NACK 也会在 COMM 中显示 `-2`。

可能出现：

- `CONFIG_PASS_NOT_MEASUREMENT,0`：写入 / 回读和两组配置保持通过，
  **不表示已验证线圈、参考时钟频率或有效转换**。没有线圈也可以做这个对照。
- `SLEEP_WRITE,-2`：`3401` 写入 NACK；即使随后值匹配也不会继续唤醒。
- `SLEEP_NOW,<负值>`：睡眠配置首次回读失败或不符；没有执行唤醒。
- `SLEEP_1S,<负值>`：首次通过，但等待 1 秒后读取失败或配置不符；没有执行唤醒。
- `WAKE_WRITE,-2`：睡眠保持通过，但 `1401` 唤醒写入收到 NACK；看两组快照。
- `WAKE_READ,-2`：唤醒写入 ACK，但静默后的第一次 CONFIG 回读失败。
- `HOLD,-18`：第一次 CONFIG 可能正确，但随后至少一个稳定配置不符。
- `RESET/ID/CONFIG_WRITE/CONFIG_READ/RESET_CONFIG`：尚未执行睡眠模式配置或唤醒。

如果这个最小工程能保持配置，而正式工程不能，应继续排查集成差异；
如果它也出现相同默认值快照，说明关闭应用服务仍未消除异常，
**不能仅凭这个结果就判定电源、SD、芯片或某一行代码一定有问题**。
正常测量仍需之后装上传感器再验证。

与 V4 对比时：若 V5 配置保持通过，说明结果与参考选择路径相关，不能直接认定外部晶振坏了；
若仍 NACK 并回到默认值，说明单独取消外部参考选择未消除异常，不再把问题仅归因于 40 MHz。
