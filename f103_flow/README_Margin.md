# V9：固定接线的软件 I²C 时序留余量版

Keil5 只打开 `MDK-ARM/LDC1614_F103_Margin_STLink.uvprojx`，只有一个目标
`LDC1614_F103_MARGIN_SW`。已带 ST-Link 下载设置，不需要选择 A/B/C 或修改宏。
Rebuild 后手动 Download，退出 Debug 连续运行；串口仍为 115200、8N1。

启动必须看到：

```text
$B,FW,C011_LDC_F103_FLOW_V9_MARGIN
$B,PROFILE,TIM14_MARGIN_OD
```

HEX 为 `MDK-ARM/Objects_Margin/LDC1614_F103_MARGIN_SW.hex`。
原 V8 的入口、输出目录和 A/B/C 基准底层均保留，没有覆盖它们的 HEX。
这是初始化和原始数据验证工程，不是完整距离测量应用；没有线圈仍不能证明测量通过。

## 不变的部分

- PB7=SCL、PB6=SDA；PA2=TX、PA3=RX、PA4 仅输入。
- MCU HSE 8 MHz 直接运行，TIM14 1 MHz 计时。主控时钟失败会明确报告 HSI_FALLBACK。
- `Device/ldc1614.c` 与原 F103 实现相同，原初始化的 15 笔事务顺序不变。
  仍是一次 `1C=8000` 软复位、确认 ID、原通道配置，最后按原算法写 `CONFIG=0A01`。
  没有额外写 `2A01`、1 秒睡眠、LDC 内部参考回退、逐寄存器插入回读或失败重试。
- LDC 选择外部 40 MHz 参考；INTB 不参与 I²C，初始化通过后等待 20 ms 再轮询。
- 不启用 SysTick、ADC、OLED、按钮服务或 MCU 看门狗，原 OLED/按钮源码不删。

## 本次改变的部分

只替换软件 I²C 底层为 `Driver/margin_i2c.c`，不再编译 B 的 `wake_i2c.c`。
GPIO 始终开漏，输出 1 是释放，不是推挽拉高。事务中不切换 GPIO 输入/输出方向。
SCL 拉低后确认 IDR 低，释放后确认 IDR 高，再开始相应阶段的计时。

依据 TI LDC1614 数据手册 SNOSCY9A 第 6.6、7.5.1、7.5.2 节：

| 阶段 | TI 下限 | 本版安排的最短等待 |
| --- | --- | --- |
| SCL 低电平 | 1.3 µs | 确认低后至少 20 µs |
| SCL 高电平 | 0.6 µs | 确认高后至少 18 µs |
| 数据建立 | 0.1 µs | 写 SDA 后至少 8 µs，再释放 SCL |
| 数据保持 | 0 µs | 确认 SCL 低后至少 2 µs，再改变 SDA |
| START 保持/reSTART 建立 | 0.6 µs | 各至少 8 µs |
| STOP 建立 | 0.6 µs | 确认 SCL 高后至少 8 µs，再释放 SDA |
| STOP 到下一 START 空闲 | 1.3 µs | 两线连续高至少 10 µs |

上述等待另加 1 个计时器 tick，避免整数微秒量化把等待缩短。
TI 表中的 0.9 µs `tVD;DAT/tVD;ACK` 是器件的输出有效时间规格，
不是让主机在上升沿后 0.9 µs 内读完或超时的要求。
LDC 不使用时钟拉伸，但主机仍检查 SCL 实际状态；线路等待上限为 2 ms。

ACK 在同一个第九拍高电平内，按确认高后的 5/9/13 µs 截止时间等待再读取；
每次读取都同时检查物理 SCL/SDA。编译器、寄存器访问会增加执行时间，
所以日志报告实际采样偏移，**不是声称采样精确发生在这三个时刻**。
三次 SDA 全低才 ACK，全高为 NACK，混合为 -5，不进行多数投票、不忽略错误。
无论 ACK/NACK 都完成第九拍再 STOP；严重线路故障时不能保证有效 STOP，另报 stop_rc。
读取高字节后主机发送 ACK，最后低字节后发送 NACK，再 STOP。
reSTART 不插 STOP；START 后没有主动释放再拉低 SDA 的多余脉冲。

位传输使用直接寄存器操作和定时器，不使用空循环估时。整笔事务保存/屏蔽/恢复
PRIMASK，不改变调用前的中断屏蔽状态。串口、除法、记录复制不放在 ACK 采样窗口中。
初始化只检查总线，不自动发清总线脉冲，也不在失败后主动复位/重新配置 LDC。

## 如何看本版日志

请保存从 `$B,FW` 到 `$B,RESULT` 以及后面的 `$M` 两行。

- `$F,FIRST,...`：首个失败的原初始化事务，后续监控不会覆盖。
- `$A,FIRST,槽,字节,采样数,SDA掩码,SCL掩码,rc,t0,t1,t2,高电平时间`：
  新增的末四项单位为定时器 µs；65535 表示没有有效测量。
- `$M,FIRST_ERROR,已捕获,低最小,低最大,高最小,高最大,周期最小,周期最大,时钟数,rc`：
  首个底层错误的计时摘要；它可能来自初始化总线检查或后续快照，
  `$F,FIRST` 则只针对原初始化事务。已捕获=0 时其余字段无意义。
- `$M,LAST,...` 是最后一笔诊断读取，不要把它当作首错事务。
- 周期统计覆盖连续数据/ACK 时钟和字节间处理时间，不包含 START/reSTART/STOP
  及两笔事务之间的等待。原有 `$F` 中的 Hz 仍是最后发送字节的 8 个周期平均估算。
- 手册 fSCL 范围是 10–400 kHz；本版不宣称 100 kHz。
  若日志周期最大值超过 100 µs，须继续检查开销/时钟，不能宣称所有频率要求已满足。
- ID 确认应为 `5449/3055`。若首错为 `ADDR_W,255,54`，表示地址无 ACK，
  尚未发寄存器/数据；若是 CONFIG 最后字节 NACK，则要按该阶段另行分析。

## 已验证与未验证

`tools/run_margin_tests.ps1` 执行真实底层、原 F103 驱动和适配层；模型从 GPIO 边沿
解码协议，不是直接让读取函数返回成功。覆盖时序下限、256 组互补字节读写、
第九拍/主机 ACK/NACK、重复起始、STOP/tBUF、定时回绕、延迟上升沿、延迟从机输出、
寄存器访问开销变化、每个发送位置 NACK、混合 ACK、SCL 错采样、卡线/超时、
STOP 失败、恢复原 PRIMASK，以及原初始化每笔事务失败后中止与首错保留。

原事务级 21 场景、A/B/C 回归也继续运行。
`tools/keil_margin_build.cmd` 只编译；不会烧录、连接 ST-Link、复位或修改选项字节。

数字模型和计时器统计都不等于示波器。它们无法证明 LDC 引脚处的模拟上升/下降时间、
电压门限、毛刺、供电瞬态、SD 干扰和接触稳定性。NACK 仍不单独证明是软件或硬件。
不要在位传输中单步暂停；可在 `f103_flow_done_checkpoint` 观察
`g_flow_debug`、`g_flow_bus`、`g_margin_first_error`。
