# STM32C011F6U6TR / LDC1614 最小 ACK 与 ID 测试

这是新写的独立测试固件，不编译原测量应用、旧 `hard_i2c.c`、OLED、按键、
ADC、Flash 参数、滤波、标定或 INTB 中断，也不写 LDC 配置寄存器。
仅复用父工程的 ST 官方 CMSIS 启动文件、系统文件和头文件；不要单独移动此目录。
时钟设置使用少量 LL 内联函数，其余使用 CMSIS 寄存器，不调用 HAL。

## 接线依据

按本次原理图，MCU 端口名与网络标签有交叉，不能按网络标签当成端口名：

| 信号 | MCU 实际管脚 | 图上网络标签 | LDC1614 |
| --- | --- | --- | --- |
| SCL | PB7，UFQFPN20 第 19 脚 | PB6 | 第 1 脚 SCL |
| SDA | PB6，UFQFPN20 第 18 脚 | PB7 | 第 2 脚 SDA |
| 串口 TX | PA2，第 7 脚 | TX | 接串口工具 RX |
| 串口 RX | PA3，第 8 脚 | RX | 接串口工具 TX；本程序不处理命令 |
| INTB | PA4，第 9 脚 | PA4 | 仅输入观察，不启用中断 |

保持图中 4.7 kΩ 上拉到 3.3 V、SD 接低、ADDR 接低，以及现有 40 MHz CLKIN。
本测试不配置采样，因此不能用它验证 40 MHz 或线圈的测量性能。

## 编译、下载

1. 打开 `MDK-ARM/LDC1614_ACK_Test.uvprojx`，不要打开父目录的测量工程。
2. 选择 `LDC1614_ACK_Test`，用 Keil 5 / ARM Compiler 6 编译。
3. 使用现有 ST-Link、SWD 下载。下载测试固件会替换板上原测量程序。
4. 串口设置 `115200 8N1`；建议模块与 MCU 完全断电再上电，采集几轮输出。

命令行只编译，不自动下载：

```bat
tools\keil_build.cmd rebuild
```

输出 `MDK-ARM/Objects/LDC1614_ACK_Test.hex`。

## 与原驱动不同之处

- I2C 是独立重写的传统半拍等待实现，没有旧诊断调度、频率校准或接线矩阵。
- TIM14 以 1 MHz 连续计数；每半拍等待至少 5 μs，另有软件开销。
  不能把它直接宣称为实测 100 kHz；`$D` 中 `hz` 为本机计时估计。
- SDA 在从机 ACK 和读取数据期间明确切为输入，SCL 拉低后才恢复开漏输出。
- START、8 位发送、第 9 拍 ACK、重复 START、两字节读取、末字节 NACK、STOP
  均在此新驱动中实现。SCL 等待超时为 2 ms，16 位差值处理定时器回绕。
- 系统优先使用 HSE 8 MHz；失败则明确报告 HSI 回退。没有 PLL，也没有 SysTick 中断。
- 启动等待 100 ms；约每秒重复测试 0x2A 和 0x2B，失败后也继续完整 ID 读取尝试。
- 只发地址和读取 ID 所需的寄存器指针 0x7E/0x7F，不软复位、不写配置或数据。

## 如何判断

版本必须是：

```text
$B,FW,C011_LDC_ACK_TEST_V1
```

诊断行：

```text
$D,<PROBE/MID/DID>,<7位地址>,<rc>,<stage>,<最近发送字节>,<ACK电平>,<lines>,<clocks>,<hz>,<stop_rc>
```

地址和字节为十六进制，其余数字为十进制。`rc=0` 成功、`-2` NACK、`-1`
总线异常/超时、`-3` 参数错误。`ACK电平=0` 应答，`1` 不应答，`255` 尚未采样。
`lines` 的 bit0=SCL、bit1=SDA；失败时为 STOP 前现场，成功时为 STOP 后空闲电平。
`clocks` / `hz` 属于最近发送字节，不是整个事务；未完成 9 拍时 `hz=0`。
`stop_rc` 单独报告清理 STOP 是否成功，不覆盖前一个错误阶段。

每个地址的汇总：

```text
$L,<addr>,<probe_rc>,<mid_rc>,<mid_hex>,<did_rc>,<did_hex>,<结论>
```

成功示例（只是格式示例，不是实板结果）：

```text
$L,2A,0,0,5449,0,3055,LDC1614_FOUND
```

只有两个 ID 都成功读回且匹配，才显示 `LDC1614_FOUND`。仅收到 ACK 不等于
确认器件型号。失败时 ID 的 `0000` 是占位，必须结合返回码，不是实际寄存器值。
`$B,ROUND,<序号>,<空闲lines>,<INTB电平>` 的 INTB 值不会参与通信判定。

本机编译和数字模型测试不能证明实板已经能应答，请提供至少两轮完整串口输出。

## 本机验证

执行 `tools/run_tests.ps1` 可用 GCC 运行独立的开漏从机模型。模型根据线上
实际收到的字节决定 ACK，验证 0x2A/0x2B、读 ID、重复 START、末字节 NACK、
普通 7 位地址移位、错误阶段、总线释放、16 位定时器回绕及卡线超时/恢复。
测试明确检查 ACK 与接收时 SDA 为输入，且不存在配置寄存器数据写入。

Keil 完整编译和主机测试均已通过；板上结果尚未验证。详细代码大小见
`MDK-ARM/build.log`，编译过程中不会自动烧录。
