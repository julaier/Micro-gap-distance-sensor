# STM32C011F6U6TR 引脚分配与串口协议

## 一、MCU 引脚

| 功能 | 引脚 | 复用 / 配置 |
| --- | --- | --- |
| USART2_TX | PA2 | AF1，接外部 CH340 RXD |
| USART2_RX | PA3 | AF1，接外部 CH340 TXD |
| LDC1614 INTB | PA4 | EXTI4_15，下降沿中断 |
| 软件 I2C SCL | PB7（19 脚） | GPIO 开漏，外部 4.7 kΩ 上拉 |
| 软件 I2C SDA | PB6（18 脚） | GPIO 开漏，外部 4.7 kΩ 上拉 |
| HSE_IN | PC14 | 8 MHz 晶振，12 pF 负载 |
| HSE_OUT | PC15 | 8 MHz 晶振，12 pF 负载 |
| SWDIO | PA13 | SWD 调试和下载 |
| SWCLK | PA14 | SWD 调试和下载 |

PA0/PA1、OLED 和复位按键不用于新硬件。PA0/PA1 按键驱动和 OLED
驱动保留在代码中，但不启用 OLED。

## 二、时钟

- MCU：外部 8 MHz 无源晶振，HSE 直接作为 SYSCLK。
- STM32C011 没有 PLL，不能把 8 MHz 倍频到 48 MHz。
- HSE 故障时固件退回 HSI 48 MHz，并通过串口报告 `CLOCK_UNEXPECTED`。
- LDC1614：独立外部 40 MHz 有源晶振接 CLKIN。
- USART2：115200 8N1，时钟由 MCU PCLK1 提供。

## 四、周期上报协议

```text
$R,<ch0>,<ch1>,<比值>,<距离mm>,<温度C>,<状态>\r\n
```

默认每 100 ms 上报一次：

```text
$R,11284266,11580266,0.97443,0.520,28.5,1
```

状态：

| 值 | 含义 |
| ---: | --- |
| 0 | 正常 |
| 1 | 提醒 |
| 2 | 报警 |
| 3 | 故障 |
| 4 | 未标定 |

启动和故障信息：

```text
$B,BOOT,HSE8M
$B,FW,C011_SW_I2C_V5_TARGET100K
$B,LDC1614 ready
$E,<错误码>
$I,<pd>,<pu>
$P,<addr>,<ack>
$X,<tag>,<rc>,<stage>,<byte>,<lines>
$G,<idle>,<scl_low>,<sda_low>,<released>
$T,<tag>,<period_min_us>,<period_max_us>,<clocks>
$W,<tag>,<tx_hex>,<sampled_hex>,<ack_mask>,<sda_mode>,<sda_od>
$M,<tag>,<probe_rc>,<mid_rc>,<mid_hex>,<did_rc>,<did_hex>
```

`$X` 输出恢复前保存的首次错误：`rc=-2` 为 NACK，`rc=-1` 为总线异常/超时。
`stage` 标识 START、ADDR_W、WRITE、RESTART、ADDR_R、READ 或 STOP 阶段；
`byte` 是从 0 开始的数据字节下标；`lines` 的 bit0=SCL(PB7)、bit1=SDA(PB6)。
GPIO 自检预期为 `$G,3,2,1,3`，只能证明 MCU 端电平可控，不能证明外部接线连通。

V3 起使用 TIM14 1 MHz 计数产生软件 I2C 延时，`$T` 是每个字节内相邻 SCL
高电平确认点的周期粗测；单位 μs。完整字节及 ACK/NACK 的 `clocks` 为 9。
频率约为 `1000000 / 周期微秒数` Hz，外部电气波形仍以示波器或逻辑分析仪为准。

V4 的 `$W` 记录逐位 SDA 读回和 ACK 前/中/末的电平（`ack_mask` 的 bit0/1/2）。
`sda_mode` 为实际 GPIO 模式（0=输入、1=输出），`sda_od=1` 表示开漏。
`$M` 仅在初始化失败后进行 8 项受控对照；标签如 `76OD2A` 表示
PB7 SCL/PB6 SDA、开漏释放接收、地址 0x2A，`76IN2A` 改为显式输入接收，
`67...` 为临时交叉映射；两个 ID 的成功返回码须均为 0，值为 `5449` / `3055`。
测试后一定恢复 PB7 SCL/PB6 SDA、开漏接收，并打印 `I2C_RESTORED`。
详细判读和验证范围见 README 的“V4 受控对照诊断”。

当前应用会读取 USART2_RX，但尚未启用电脑端命令解析。
